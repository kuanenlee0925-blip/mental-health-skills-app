2. A surprising timer failure found during development

On October 24, separately rounding wall and excluded time made active time move backwards by 1 millisecond while paused. SQLite rejected that save as a backwards checkpoint. The earlier unfinished record was preserved as evidence, not rewritten as successful.

Old calculation (historical reconstruction):
active = round(wall) - round(excluded)

900.4 ms of actual practice:
round(5000.6) - round(4100.2) = 901
round(5001.0) - round(4100.6) = 900

Observed consequence: a later checkpoint can be smaller.

Decision: round active time itself, then derive excluded time. A regression test samples fractional pause times and requires all checkpoints to remain at 900 ms. This page explains the recorded failure; it does not claim the old bug is still in the current app.

3. Explain the generated code

  snapshot(now) {
    const end = this.ended ?? now
    const wall = Math.max(0, Math.round(end - this.started))
    // Round active time itself so fractional pause samples cannot make a saved
    // active duration move backwards by 1 ms when wall/excluded round separately.
    const active = Math.min(wall, Math.max(0, Math.round((this.pauseAt ?? end) - this.started - this.excluded)))
    const excluded = wall - active

end freezes once the exercise ends. While paused, pauseAt freezes active time. Completed pauses are accumulated in excluded. Deriving excluded time from wall minus active preserves the accounting identity. The model never controls this timer, Stop, or support.

The intended sequence remains six 4-second inhales and 6-second exhales. User pauses are reported separately. A hidden tab or long scheduling gap is interrupted, never rushed to completion.
